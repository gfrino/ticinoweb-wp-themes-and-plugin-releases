- **Fix**: The contact-page form and the "Schedule service" modal did not send anything. Neither form had `name` attributes or a submit handler, so "Send" simply reloaded the page: no email, no stored submission (the site's `ticinoweb_form_submissions` table was empty). Found while answering the client's question "where are the email requests from the website being sent?".
- **Feature**: New `inc/forms.php` wires both forms to the parent theme's AJAX handler (`ticinoweb_submit_form`): fresh nonce via `ticinoweb_form_token` (pages are cached for days, so a nonce printed in the HTML would be stale), honeypot `tw_hp`, inline success/error notice, button disabled while sending. Submissions are saved in ticinoWEB CMS → "Invii Ricevuti" and emailed to the site's contact email (`ticinoweb_contact_email`, fallback admin email) — per site, nothing hardcoded.
- **Fix**: reCAPTCHA v3 was verified server-side (the site has a secret key) but nothing ever loaded the Google script, so every submission would have failed the anti-spam check. The script is now enqueued only when the site has a site key.
- **Change**: `name` attributes on all fields (`nome`/`cognome` merged client-side, `email`, `telefono`, `oggetto` = the service select, `messaggio`). The modal gained a required Email field, because the handler needs a valid address for the Reply-To.
- **Note**: Success message is the theme's own English text; the parent's response message is Italian.
